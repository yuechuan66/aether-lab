# DSH Session Flow Visualizer — 技术设计方案

> **版本**：v1.0
> **日期**：2026-08-24
> **状态**：Draft

## 1. 背景与目标

### 1.1 背景

DSH 基于 Cordis 插件内核，一次会话涉及 **Agent 步骤 → 模型请求/流式输出 → 工具执行流水线 → Session 事件** 多阶段协作。当前调试手段无法直观呈现单次会话中事件的完整流转路径、各扩展点的介入时序与耗时分布。

### 1.2 目标

| # | 目标 | 衡量标准 |
|---|------|----------|
| G1 | 实时可视化单次会话的完整数据流转过程 | 从用户发送到最终响应，每个 Hook/Tool 节点可见 |
| G2 | 展示插件间的调用关系与执行顺序 | 时序图 + 泳道图 |
| G3 | 支持展开查看每个节点的输入/输出快照 | 点击节点可查看 JSON |
| G4 | 对会话性能影响 < 5% | 基准测试对比 |
| G5 | 可作为独立插件安装/卸载，不侵入 DSH 核心 | `npm install / uninstall` 即可 |

### 1.3 非目标（本期不做）

- 跨会话聚合分析 / 统计报表
- 生产环境 APM 级别监控
- 断点调试 / 手动修改变量后继续执行

## 3. 数据模型

### 3.1 核心事件结构

```typescript
/** 单条数据流事件 */
interface FlowEvent {
  /** 全局唯一 ID */
  id: string;
  /** 所属会话 ID */
  sessionId: string;
  /** 所属 Trace（一次完整请求-响应为一个 Trace；关联规则见 4.3） */
  traceId: string;
  /** 父事件 ID（用于嵌套调用，如 tool 内部再调 model） */
  parentId: string | null;
  /** 事件产生的时间戳 (ms) */
  timestamp: number;
  /** 阶段标识 */
  phase: FlowPhase;
  /** 产生此事件的插件名（无法从事件取得时为空） */
  pluginName: string;
  /** 耗时 (ms)，异步事件在结束时回填 */
  duration: number | null;
  /** 输入快照（截断至 1KB） */
  input: SnapshotValue | null;
  /** 输出快照（截断至 1KB） */
  output: SnapshotValue | null;
  /** 扩展元数据 */
  metadata: Record<string, unknown>;
  /** 状态 */
  status: 'running' | 'success' | 'error' | 'skipped';
}

type FlowPhase =
  | 'session.created'
  | 'agent.pre-step'
  | 'agent.request'
  | 'llm.stream'
  | 'tools.pre-execute'
  | 'tools.execute'
  | 'tools.post-execute'
  | 'tools.result'
  | 'session.event'
  | 'agent.request-error'
  | 'agent.error'
  | 'session.disposed';

// DSH 当前没有原生 traceId/spanId。插件按 sessionId + turn + step 建立 Trace，
// 工具调用通过 session/event 中的 callId 关联。
type SnapshotValue = string | number | boolean | object | null;

```

### 3.2 Trace 聚合结构

```typescript
/** 一次完整用户请求的 Trace */
interface FlowTrace {
  traceId: string;
  sessionId: string;
  startTime: number;
  endTime: number | null;
  events: FlowEvent[];
  totalDuration: number | null;
  totalTokens: { input: number; output: number } | null;
  toolCallCount: number;
  status: 'running' | 'completed' | 'failed';
}
```

## 4. 后端：Flow Tracer Plugin 设计

### 4.1 插件入口

```typescript
// src/index.ts
import { Context } from '@cordisjs/core';
import { Collector } from './collector';
import { Emitter } from './emitter';
import { FlowConfig } from './types';

export const name = 'dsh-plugin-flow-tracer';

export function apply(ctx: Context, config: FlowConfig = {}) {
  const opts: Required<FlowConfig> = {
    port: config.port ?? 9527,
    transport: config.transport ?? 'sse',
    maxBufferSize: config.maxBufferSize ?? 2000,
    snapshotLimit: config.snapshotLimit ?? 1024,
    enabled: config.enabled ?? true,
    ...config,
  };

  if (!opts.enabled) return;

  const collector = new Collector(opts);
  const emitter = new Emitter(opts, collector);

  // 注册各阶段采集
  registerHooks(ctx, collector);

  // 启动 SSE/HTTP 服务
  emitter.start();

  // 插件卸载时关闭 SSE 客户端和 HTTP Server
  ctx.effect(() => async () => {
    await emitter.close();
  }, 'dsh-plugin-flow-tracer');

  ctx.command('/flow', '查看当前会话数据流')
    .option('--json', '以 JSON 格式输出')
    .action(({ options }, session) => {
      const trace = collector.getTrace(session.id);
      return options.json
        ? JSON.stringify(trace, null, 2)
        : formatTimeline(trace);
    });

  // 会话结束由 session/disposed 记录；插件卸载由 ctx.effect 清理 Emitter。
}

```

### 4.2 采集器（Collector）

Collector 区分 Waterfall 和普通事件。Waterfall 包装器记录开始、结束、异常，并调用 `next()`；普通事件只记录事件事实。

```typescript
// src/collector.ts
export class Collector {
  private traces: Map<string, FlowTrace> = new Map();
  private traceByStep: Map<string, string> = new Map();
  private sequence = 0;

  constructor(private opts: Required<FlowConfig>) {}

  startTrace(sessionId: string, turn: number, step: number) {
    const traceId = `${sessionId}:${turn}:${step}`;
    if (!this.traces.has(traceId)) {
      this.traces.set(traceId, {
        traceId,
        sessionId,
        startTime: Date.now(),
        endTime: null,
        events: [],
        totalDuration: null,
        totalTokens: null,
        toolCallCount: 0,
        status: 'running',
      });
    }
    this.traceByStep.set(`${sessionId}:${turn}:${step}`, traceId);
    return traceId;
  }

  endTrace(sessionId: string, turn: number, step: number, status: FlowTrace['status']) {
    const traceId = this.traceByStep.get(`${sessionId}:${turn}:${step}`);
    const trace = traceId && this.traces.get(traceId);
    if (!trace) return;
    trace.endTime = Date.now();
    trace.totalDuration = trace.endTime - trace.startTime;
    trace.status = status;
  }

  wrapWaterfall(phase: FlowPhase) {
    return async (payload: unknown, next: () => Promise<unknown>) => {
      const event = this.createEvent(phase, payload);
      this.push(event);
      try {
        const result = await next();
        event.duration = Date.now() - event.timestamp;
        event.output = this.snapshot(result);
        event.status = 'success';
        this.update(event);
        return result;
      } catch (error) {
        event.duration = Date.now() - event.timestamp;
        event.status = 'error';
        event.metadata.error = error instanceof Error ? error.message : String(error);
        this.update(event);
        throw error;
      }
    };
  }

  record(phase: FlowPhase, payload: unknown) {
    const event = this.createEvent(phase, payload);
    event.status = 'success';
    this.push(event);
  }

  recordSessionEvent(session: unknown, event: unknown) {
    // session 是完整 Session 对象，含循环引用，禁止整体序列化。
    // 只提取 event（type/seq/time/data），sessionId 单独取出。
    const sessionId = (session as { id?: string })?.id
    const ev = event as { type?: string; seq?: number; time?: number; data?: unknown }
    const traceId = this.resolveTraceId(sessionId, ev.data)
    const flowEvent: FlowEvent = {
      id: `evt-${++this.sequence}`,
      sessionId: sessionId ?? '',
      traceId,
      parentId: null,
      timestamp: ev.time ?? Date.now(),
      phase: 'session.event',
      pluginName: this.resolvePluginName(ev),
      duration: null,
      input: this.snapshot(ev.data),
      output: null,
      metadata: { seq: ev.seq, type: ev.type },
      status: 'success',
    }
    this.push(flowEvent)
  }

  private resolveTraceId(sessionId: string | undefined, data: unknown): string {
    const d = data as { turn?: number; step?: number } | undefined
    if (sessionId && d?.turn !== undefined && d?.step !== undefined) {
      return `${sessionId}:${d.turn}:${d.step}`
    }
    return sessionId ?? 'unknown'
  }

  private resolvePluginName(ev: { type?: string; data?: unknown }): string {
    const data = ev.data as { message?: { source?: { provider?: string; model?: string; plugin?: string } }; name?: string } | undefined
    if (data?.message?.source?.plugin) return data.message.source.plugin
    if (data?.message?.source?.provider) {
      return data.message.source.model
        ? `${data.message.source.provider}/${data.message.source.model}`
        : data.message.source.provider
    }
    if (data?.name) return data.name
    return ''
  }

  private snapshot(value: unknown): SnapshotValue {
    if (value === undefined) return null
    try {
      const str = JSON.stringify(value)
      if (str === undefined) return null
      if (str.length > this.opts.snapshotLimit) {
        return str.slice(0, this.opts.snapshotLimit) + '...[truncated]'
      }
      return JSON.parse(str)
    } catch {
      return String(value)
    }
  }
}
```

DSH 没有原生 `traceId`、`spanId` 或 `traceparent`，但本方案仍需实现完整会话 Trace：插件使用 `session.id`、`turn`、`step` 建立关联，并通过 `session/event` 中的 `callId` 关联工具调用与结果。缺失原生 Trace ID 是实现约束，不是目标降级。

### 4.3 Trace 关联规则（已通过 Spike 验证）

以下规则基于 2026-08-24 对 DSH v0.1.0-rc.7 的实测（见附录 C Spike 方案）。

**关联键**：

- 会话：`sessionId`（`llm/stream` 的 `GenerateOptions.sessionId`）
- 步骤：`turn` + `step`（`agent/pre-step`、`agent/request`、`session/event` 的 `data` 中均有）
- 工具：`callId`（从模型流开始，贯穿 `tool/call` → `tools/execute` → `tools/result` → `tool/result` 全程一致）

**Trace 生命周期**（实测确认）：

1. `agent/pre-step` 首次收到 `(turn, step)` 时创建 Trace，记录 `messages` 作为请求上下文。
2. `agent/request` 与 `llm/stream` 继承当前 `(turn, step)`；`llm/stream` 提供完整模型输入（`messages`、`system`、`tools`）。
3. 模型输出来自 `session/event` 的 `assistant/message` 事件，含 `usage.inputTokens` / `outputTokens` 和 `source.provider` / `source.model`。
4. 工具调用通过 `callId` 关联 `tool/call` → `tools/pre-execute` → `tools/execute` → `tools/post-execute` → `tools/result` → `tool/result`。
5. **Trace 结束标志是 `session/event` 的 `step/end`**（`data` 含 `turn` + `step`），不是 `session/disposed`。收到 `step/end` 后将 Trace 标记为 `completed`。
6. `agent/request-error`、`agent/error` 将当前 Trace 标记为 `failed`。
7. `session/disposed` 只表示会话销毁，用于清理该会话所有 Trace。

**插件身份来源**（实测确认）：

- 模型调用：`session/event(assistant/message)` 的 `data.message.source.provider` 和 `source.model`
- 工具调用：`session/event(tool/call)` 的 `data.name` 和 `tools/execute` 的 `exec.name`
- 系统消息：`session/event` 的 `data.message.source.plugin`（仅部分事件携带）

DSH 事件本身不提供通用 `pluginName` 字段；泳道按 `provider` / `model` / 工具名分组，而不是按未知插件名。

> TODO（v1.1）：向 DSH 上游提交 PR，在 `ToolDefinition` 增加 `source` 字段（工具注册时携带插件名），使工具调用事件能精确定位到注册插件，移除 `toolToPlugin` 映射表和"未知插件"标注。当前 DSH 运行时在 `register()` 处丢弃调用者身份，信息无法事后重建。

**`llm/stream` 过滤**（实测确认）：

`llm/stream` 会被触发多次，包括会话标题生成等辅助请求。需过滤 `GenerateOptions.purpose` 非主请求的流，或按 `turn` / `step` 关联到当前 Trace。

### 4.4 Hook 注册

DSH 事件分两类，不能统一使用 `(data, next)` 包装器：

- **Waterfall**：`agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`、`tools/execute`、`tools/post-execute`。
- **普通事件**：`session/event`、`tools/result`、`agent/request-error`、`agent/error`、`session/created`、`session/flush`、`session/disposed`。

```typescript
// src/hooks.ts
function registerHooks(ctx: Context, collector: Collector) {
  // Waterfall：必须调用 next()，否则短路
  ctx.on('agent/pre-step', collector.wrapWaterfall('agent.pre-step'));
  ctx.on('agent/request', collector.wrapWaterfall('agent.request'));
  ctx.on('llm/stream', collector.wrapLlmStream());        // 过滤非主请求
  ctx.on('tools/pre-execute', collector.wrapWaterfall('tools.pre-execute'));
  ctx.on('tools/execute', collector.wrapWaterfall('tools.execute'));
  ctx.on('tools/post-execute', collector.wrapWaterfall('tools.post-execute'));

  // 普通事件：只读记录
  ctx.on('session/created', (session) => collector.record('session.created', session));
  ctx.on('session/event', (session, event) => collector.recordSessionEvent(session, event));
  ctx.on('tools/result', (exec, result) => collector.record('tools.result', { exec, result }));
  ctx.on('agent/request-error', (payload) => collector.record('agent.request-error', payload));
  ctx.on('agent/error', (payload) => collector.record('agent.error', payload));
  ctx.on('session/disposed', (session) => collector.record('session.disposed', session));
}
```

DSH 没有 `model/request`、`model/response`、`tool.execute`、`session.start`、`session.end`。模型输入来自 `llm/stream` 的 `GenerateOptions.messages`；模型输出和 token 统计来自 `session/event` 的 `assistant/message`。

### 4.5 推送器（Emitter）

```typescript
// src/emitter.ts
import http from 'node:http';

export class Emitter {
  private clients: Set<http.ServerResponse> = new Set();
  private server?: http.Server;

  constructor(
    private opts: Required<FlowConfig>,
    private collector: Collector,
  ) {}

  start() {
    this.server = http.createServer((req, res) => {
      // SSE 端点
      if (req.url === '/events' && req.method === 'GET') {
        res.writeHead(200, {
          'Content-Type': 'text/event-stream',
          'Cache-Control': 'no-cache',
          'Connection': 'keep-alive',
          'Access-Control-Allow-Origin': '*',
        });
        this.clients.add(res);
        req.on('close', () => this.clients.delete(res));
        return;
      }

      // REST：获取完整 Trace
      if (req.url?.startsWith('/trace/') && req.method === 'GET') {
        const sessionId = req.url.split('/trace/')[1];
        const trace = this.collector.getTrace(sessionId);
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify(trace));
        return;
      }

      // 静态文件：前端页面
      this.serveStatic(req, res);
    });

    this.server.listen(this.opts.port, '127.0.0.1', () => {
      console.log(`[flow-tracer] Viewer at http://localhost:${this.opts.port}`);
    });
  }

  async close() {
    for (const client of this.clients) client.end();
    this.clients.clear();
    if (!this.server) return;
    await new Promise<void>((resolve, reject) => {
      this.server!.close((error) => error ? reject(error) : resolve());
    });
    this.server = undefined;
  }

  /** 广播事件给所有连接的客户端 */
  broadcast(event: FlowEvent) {
    const data = `data: ${JSON.stringify(event)}\n\n`;
    for (const client of this.clients) {
      client.write(data);
    }
  }
}

```

### 4.6 `llm/stream` 采集策略

`llm/stream` 的 `GenerateOptions` 含 `purpose?: 'compaction' | 'session-title'`。普通对话请求**不设置** `purpose`，因此：

```typescript
// Collector 增加
wrapLlmStream() {
  return (options: GenerateOptions, next: () => AsyncIterable<StreamChunk>) => {
    // 辅助请求（compaction / session-title）不采集
    if (options.purpose) return next()

    this.record('llm.stream', {
      sessionId: options.sessionId,
      provider: options.provider,
      model: options.model,
      messages: this.snapshot(options.messages),
      system: options.system,
      tools: options.tools,
    })

    // MVP：不包装流，只记录输入与耗时。
    return next()
  }
}
```

**决策**：MVP 不包装流式 chunk，只记录模型输入和开始时间；模型输出、`usage` 从 `assistant/message` 事件获取。v1.1 再考虑流式过程观测。

### 4.7 SSE 消息协议

SSE 事件通过 `event:` 字段区分类型：

| event 类型 | 载荷 | 触发时机 | 前端处理 |
|-----------|------|---------|---------|
| `trace.list` | `{ traceIds: string[] }` | 连接建立 | 填充会话选择器 |
| `trace.init` | 完整 `FlowTrace` | 连接建立 | 初始渲染 |
| `event` | `FlowEvent` | 单个事件产生 | 追加到时间线 |
| `trace.end` | `{ traceId, status, duration }` | Trace 完成 | 标记完成 |

```typescript
// Emitter 增加
send(type: string, payload: unknown) {
  const data = `event: ${type}\ndata: ${JSON.stringify(payload)}\n\n`;
  for (const client of this.clients) client.write(data);
}
```

前端 `EventSource` 监听：

```typescript
const es = new EventSource('http://127.0.0.1:9527/events');
es.addEventListener('trace.list', (e) => { /* 填充选择器 */ });
es.addEventListener('trace.init', (e) => { /* 初始渲染 */ });
es.addEventListener('event', (e) => { /* 追加节点 */ });
es.addEventListener('trace.end', (e) => { /* 标记完成 */ });
```

### 4.8 快照安全性

`session/event` 的 `session` 参数是完整 Session 对象（含循环引用），**禁止整体序列化**。Collector 只提取：

- `session.id` → `sessionId`
- `event.type` / `event.seq` / `event.time` / `event.data` → 事件内容

`snapshot()` 必须安全处理：

1. `JSON.stringify` 失败（循环引用、`BigInt`）时降级为 `String(value)`。
2. 截断按字符数处理（`snapshotLimit`），不保证 UTF-8 字节边界。
3. 脱敏在 `snapshot` 之前完成，对对象递归处理。

## 附录 C：Spike 方案与验证结果

### C.1 目标

验证 DSH 当前版本（v0.1.0-rc.7）的事件采集可行性，确认以下四点：

1. `llm/stream` 能否作为模型输入输出的采集点
2. `agent/request` 与 `llm/stream` 的关联字段
3. 工具 `callId` 在 `tools/execute`、`tool/call`、`tool/result` 中是否一致
4. 插件名的可获取性

### C.2 探针插件

文件：`spike/probe.ts`（探针监听所有候选事件并打印 payload）

```typescript
import type { Context } from '@deepseek-ai/cordis'

export const name = 'flow-tracer-probe'

export function apply(ctx: Context) {
  // Waterfall：必须调用 next()
  ctx.on('agent/pre-step', async (payload: any, next: any) => {
    console.log('agent/pre-step', payload)
    return next()
  })
  ctx.on('agent/request', async (payload: any, next: any) => {
    console.log('agent/request', payload)
    return next()
  })
  ctx.on('llm/stream', (options: any, next: any) => {
    console.log('llm/stream', options)
    const stream = next()
    return {
      async *[Symbol.asyncIterator]() {
        for await (const chunk of stream) {
          console.log('llm/chunk', chunk)
          yield chunk
        }
      },
    }
  })
  ctx.on('tools/pre-execute', async (exec: any, next: any) => {
    console.log('tools/pre-execute', exec)
    return next()
  })
  ctx.on('tools/execute', async (exec: any, next: any) => {
    console.log('tools/execute', exec.callId)
    return next()
  })
  ctx.on('tools/post-execute', async (exec: any, result: any, next: any) => {
    console.log('tools/post-execute', exec.callId)
    return next()
  })

  // 普通事件：只观察
  ctx.on('tools/result', (exec: any, result: any) => {
    console.log('tools/result', exec.callId)
  })
  ctx.on('session/event', (session: any, event: any) => {
    if (event?.type?.includes('tool') || event?.type?.includes('step') || event?.type?.includes('assistant')) {
      console.log('session/event', event.type, event.data)
    }
  })
}
```

### C.4 验证结果

| 验证点 | 结果 | 证据 |
|--------|------|------|
| `llm/stream` 采集模型输入 | ✅ | `GenerateOptions` 含 `provider`、`model`、`messages`、`system`、`tools`、`sessionId` |
| `agent/request` 与模型流的关联 | ✅ | 均含 `turn`、`step`、`sessionId` |
| `callId` 一致性 | ✅ | `tool/call` → `tools/execute` → `tools/result` → `tool/result` 全程一致 |
| 插件名 | ⚠️ | 事件不带通用 `pluginName`，.provider`/`source.model`/`exec.name` 可用 |

### C.5 实际事件顺序

```text
agent/pre-step
  → session/event(step/start)     // turn + step
  → agent/request                 // turn + step + provider + model
  → llm/stream                    // 完整 messages + tools + sessionId
  → session/event(assistant/message)  // usage + provider + model + tool-call
  → session/event(tool/call)      // callId + name + arguments
  → tools/pre-execute
  → tools/execute                 // callId
  → tools/post-execute
  → tools/result                  // 最终结果
  → session/event(tool/result)    // callId 一致
  → session/event(step/end)       // turn + step，Trace 结束标志
```

### C.6 关键结论

1. Trace 结束标志是 `session/event` 的 `step/end`，不是 `session/disposed`。
2. 模型输出和 token 统计在 `session/event(assistant/message)`，不是 `model.response`（该事件不存在）。
3. `llm/stream` 会被辅助请求（如会话标题生成）触发，需按 `purpose` 字段过滤。
4. 采集架构可行，无需修改 DSH 核心。

### D.3 关键技术约束（实施中发现）

1. **DSH 用 Node strip-only 模式加载 TS**：不支持 TypeScript 参数属性（`constructor(private x)`），必须显式字段赋值。
2. **`assistant/chunk` 事件极高频**（每 token 一个），且携带大对象，必须过滤，否则 OOM。
3. **`session/event` 的 `session` 参数含循环引用**，禁止整体序列化，只提取 `id` 和 `event` 内容。
4. **工具插件名在运行时不可得**：`ToolDefinition`/`register()` 无 owner 字段，靠 `toolToPlugin` 映射表 + 上游 PR 根治。
5. **`agent.pre-step`/`agent.request` payload 无 sessionId**，需从 `session/created` 事件捕获。
6. **React 无限渲染 #310**：zustand selector 每次返回新数组会导致 "Maximum update depth exceeded"，所有派生数据必须收敛进 `useMemo`，组件体禁止每次 render 重建 Map/数组。

### D.4 插件树可视化（依赖 DAG）

本方案参照 `plugin-tree-visualization-plan.md` 实现插件树视图，关键数据结论：

1. **依赖图数据源**：`fiber.inject`（消费者，49 个非空）+ `fiber.store`（提供者，142 个服务），一次遍历 `loader.entries()` 全拿到。**无需 `Plugin.inject`、无需 `ReflectService.store`**（后者实测恒为 0）。
2. **`entry.options.inject` 恒为 0**：依赖声明在运行时 `fiber.inject` 上，不在 entry options。
3. **isolate/group 在 profile 层恒为 0**：只在 agent preset 挂载后的 session 级 loader 才有。当前 viewer 读 profile loader，故 isolate 嵌套框画不出——这是数据边界，非代码缺陷。
4. **落地形态**：ELK layered 布局（Sugiyama 分层算法），节点=插件，边=inject 依赖。实测 112 节点 / 121 依赖边。交互：hover 高亮出入边、点击看详情（provide/inject/状态）、缩放（0.3x~2x）、隐藏禁用/隐藏 UI/仅依赖节点三个过滤开关。

### D.6 事件总线视图（Cordis 调度时序）

表达"插件调度"而非"插件依赖"，核心是 Cordis 的发布-订阅模型：

**事件的三层角色**（都是插件，内核只负责分发）：
1. **定义**：插件作者 `declare module` 声明（类型层约定）
2. **触发**：核心插件在特定时机 `ctx.emit/waterfall/parallel/serial/bail(...)`
3. **监听**：任意插件 `ctx.on(...)`，事件发生时按分发模式被调度

**分发模式**（决定"调度"形态）：

| 模式 | 调度语义 |
|------|---------|
| `emit` | 广播，监听者各自执行，不等待 |
| `waterfall` | 链式，监听者依次执行，可拦截/修改 |
| `parallel` | 并发执行，等待全部 |
| `serial` | 顺序执行，首个返回值胜出 |
| `bail` | serial 同步版 |

**事件定义表**（`viewer/src/eventDefs.ts`）：静态硬编码 DSH 核心事件的分发模式 + 触发者，来自源码 `@mode` 注释（2026-08-25 核实）。

**视图形态**：三层泳道（触发者 / 事件总线 / 监听者）× 横向时间轴。事件节点 = 胶囊（显示事件名，颜色=分发模式），触发者/监听者 = 方块（显示短名），箭头 = 触发（emit）+ 调度（on）。hover 看完整详情，zoom 缩放，过滤 firehose（`session/event`）。

**已知边界**："事件 → 完整监听者列表" 的静态映射 Cordis 不暴露给外部，运行时观测只能拿到主执行者（pluginName），拿不到 waterfall 内部的完整监听器链。要补全需源码静态分析（扫 `ctx.on` 调用）。

### D.7 栈归因 Spike（2026-08-25，结论：不可行）

**目标**：不依赖 `toolToPlugin` 静态映射，运行时动态发现工具→插件归属（顺带验证事件注册者/完整监听者清单能否动态化）。

**探针**：`spike/stack-probe.ts`。包装 `Context.prototype.emit/on` 与 tools 服务 `register` 方法，在调用瞬间用 `new Error().stack` 解析 npm 包名。加载：`dsh --profile headless --patch ./spike/stack-probe.yml "<task>"`。

**结果**：

1. **机制成立**：原型补丁生效（全插件实例共享原型），栈帧解析出包名。
2. **归因粒度不存在**：DSH 以单包 bundle 分发（`@deepseek-ai/dsh`，`lib/` 下仅 5 个 hash chunk），168 个插件均为同一包内模块。所有 `emit/on` 归因恒为 `@deepseek-ai/dsh`；文件层是随版本变化的 hash 文件名，无法区分插件身份。
3. **时序**：`tools.register` 在补丁插件加载前已完成（patch insert 顺序靠后）。即使提前时序，仍受 #2 限制。
4. **附带发现**：tools 服务方法表含 `register`，`tools/change` 事件每会话约 50 次，但载荷均不携带注册者身份。

**结论**：动态发现是数据边界不可行，非实现缺陷。维持 `toolToPlugin` + `/unmapped-tools` 发现机制的过渡设计；根治仍为 D.5 #3 上游 PR（`register` 时由调用者 ctx 携带身份）。事件注册者（owner）同理：Cordis 事件无运行时注册动作，声明关系只存在于类型层，静态 `eventDefs.owner` 是唯一来源。

**完整映射表的采集（上游 PR 前的正解）**：双保险。

1. **启动时扫描已安装产物**（`src/toolmap.ts`，首选）：已安装的 `@deepseek-ai/dsh` 在自带 `node_modules` 中保留 194 个独立插件子包（边界未丢），`lib/*.js` 非压缩、注册形态稳定（`register(defineTool({ name: "X"`）。插件启动后 `setImmediate` 异步扫描（实测 267ms，不阻塞），映射与用户实际安装版本自动对齐，无需源码仓库。双归属取非 `-persistent` 包。
2. **内置默认表**（`collector.ts` 的 `KNOWN_TOOL_TO_PLUGIN`）：`scripts/gen-tool-map.py` 扫源码生成（v0.1.0-rc.7 全量 50 工具），兜底安装产物中缺失的可选包（实测已安装 31 个工具，其余靠内置表）。

优先级：用户 `toolToPlugin` 配置 > 启动扫描 > 内置表。零配置可用；`toolToPlugin` 仅用于覆盖/补充。


### D.8 Web「数据流」tab 集成与主题跟随（v0.4.0）

**扩展点**（核实自 `dsh-client-ui-trajectory` 与 `dsh-client-ui-slots`）：客户端入口 `lib/client.js` 以 `window.__ModuleLoader__.load({ id, factory })` 懒 CJS 契约注册（esbuild CJS + banner/footer 包装）；`ctx.slots.register({ name: 'conversation.view', id: 'flow', order: 20, label }, FlowTab)` 挂 tab。package.json 声明 `exports["./client"]` 与 `dsh.client.{inject,platform}`。

**形态**：FlowTab 薄壳（端口顺序探测 9527-9532、postMessage 握手诊断、独立打开兜底）+ iframe 嵌入 Viewer（`?embed=1&session=<id>&theme=`）。embed 模式无独立 header、根部透明、iframe 无边框，融入宿主 tab 区域。

**主题跟随**：宿主在 `body[data-ds-dark-theme]` 挂暗色信号（参考 dsh-plugin-agent-workflow）；FlowTab 以 MutationObserver 监听并经 postMessage 实时通知 iframe。Viewer 浅色实现 = 在 `[data-fv-theme='light']` 下重映射 Mantine `dark-*/gray-*/dimmed` CSS 变量（`viewer/src/theme.css`），零组件级改动。

**发布态踩坑记录**：
1. client bundle 必须是 `__ModuleLoader__.load` 注册形态，裸 ESM 报 "loaded without registering"。
2. 静态服务必须剥 query string（深链 `?embed=1&session=…` 曾 404 致 iframe 空白）。
3. JSON 路由需 CORS `*`（跨源探测/拉取）。
4. 同 profile 已装 bundle 时 `--patch` insert 同 id 冲突 → dev 用独立 `flowdev` profile（源码加载，9528）。
5. pnpm 对同版本 file: 依赖跳过重装 → 每次发版必须 bump 版本。
